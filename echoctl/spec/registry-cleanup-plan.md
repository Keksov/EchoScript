# registry-cleanup — план

## Проблема

`echoctl daemons stop` глушит демон жёстко (`TerminateProcess`) — демон не успевает удалить
свою регистрацию `jobs/registry/<model>.json`. Файл остаётся с протухающим heartbeat →
панель ~15с (TTL) показывает «запущен», потом «устарел» (stale) — и так до следующего старта.
Честного мгновенного «down» после stop нет. Касается всех движков (whisper, diarization).

## Решение

После УСПЕШНОГО stop (порт закрылся) echoctl сам удаляет регистрацию инстанса:
`<jobs_root>/registry/<model_name>.json` (`jobs_root` из config.json, относительный —
резолвится от repoRoot). Best-effort: нет файла/не удалился — не ошибка stop.

То же в стоп-фазе `restart`: во время долгого прогрева панель покажет честный «down»
вместо «устарел»; новый демон перепишет регистрацию сам.

## Решения

- **RC-D1** удаление после подтверждённого stop (waitPortClosed успешен) в runDaemonsStop и
  стоп-фазе runDaemonsRestart; best-effort (DeleteFile, без падений).
- **RC-D2** ключ — model_name инстанса (== имя файла регистрации, как пишут демоны).
  Нюанс: два инстанса одной модели делят файл — stop одного удалит регистрацию живого,
  тот перепишет её heartbeat'ом в ≤5с; допустимо (сама схема реестра model_name-keyed).

## Фазы

- **P0** План + леджер.
- **P1** Фикс + live-тест — gate: stop работающего демона → registry-файл удалён сразу,
  панель показывает «down» без 15с «устарел»; start → файл возвращается, «запущен».

## Конвенции

FPC по лекалу echoctl. Один шаг → один коммит → один гейт. Ветка `feature/registry-cleanup`
от master.
