# dev-tail — план

Показывать логи демона в живой WT-вкладке в dev-режиме, дёшево по памяти. Демон
остаётся без окна (socket-safe, warmup echoctl не трогаем); вкладка — отдельный
процесс, тейлящий лог-файл. Тейлер — своя FPC-утилита `echotail` (~3-5 МБ vs ~78 МБ
у pwsh `Get-Content -Wait`, замер 2026-07-08).

Методология: «План + Леджер» (`dev-tail-progress.json`). Шаг → коммит → гейт. Пауза
на границах фаз. Первый шаг — DT0.1. DAG ацикличен.

## Решения (владелец, 2026-07-08)
- **DT-D1:** dev/prod различаем по env `ECHOSCRIPT_DEV=1` (как NODE_ENV); echoctl её
  читает, наследует от Bun; работает и при ручном `echoctl daemons start`.
- **DT-D2:** тейлер — отдельная FPC CLI `echotail` (single-job, интегрируется глубже
  позже: резолв лога по имени инстанса, подсветка, статус). Не pwsh (память).
- **DT-D3:** демон запускается БЕЗ окна везде (echoctl уже так; `start_*.bat`
  унифицируем). Логи в `services/<engine>daemon/logs/<name>.log`.
- **DT-D4:** в dev echoctl после старта демона открывает `wt -w 0 new-tab echotail <log>`.
- **DT-D5:** `start_*.bat` (ручной запуск) — всегда dev-режим: демон без окна + tail-вкладка
  (если есть wt+Win11), иначе прежнее свёрнутое окно.
- **DT-D6:** tail-вкладка живёт после остановки демона (пользователь закрывает сам).

## echotail — интерфейс
```
echotail <logpath> [--tail N] [--title T]
```
- Follow файла (seek к последним N строкам, затем читать дозаписи, печатать).
- Подсветка: зелёный для ready/ok/listening, красный для error/fail/exception/fatal,
  приглушённый — рутина.
- Устойчив к отсутствию файла на старте (ждёт появления) и к ротации (файл усёкся → с начала).
- Память ~ RTL + буфер (единицы МБ). Ctrl-C для выхода; вкладка остаётся.

## Фазы
| Фаза | Содержание | Гейт |
|---|---|---|
| **P0** | план + скелет echotail (build/run/smoke) | build зелёный; `echotail --help`/version |
| **P1** | follow-логика + подсветка + устойчивость (нет файла/ротация) | смоук: дозаписи появляются, ключевые строки подсвечены |
| **P2** | интеграция: echoctl dev-режим (ECHOSCRIPT_DEV → tail-вкладка); unify `start_*.bat`; dev-скрипты выставляют env | dev → вкладка с логом; prod → без окна; память лёгкая |
| **P3** | E2E + docs | демон из панели(dev)/скрипта → живой лог во вкладке; README |

## Риски
- `wt -w 0` из фонового Bun таргетит последнее окно WT — приемлемо (или новое).
- echotail должен открывать лог с shared-read (демон пишет одновременно).
- Юникод в логах (кириллица) — echotail печатает байты как есть; консоль WT в UTF-8.
