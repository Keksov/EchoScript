# tab-reuse — план

## Проблема

Повторный запуск демона (dev start / already-running / `daemons tabs`) каждый раз открывает
НОВУЮ echotail-вкладку на тот же лог — вкладки плодятся.

## Решение (владелец: «переиспользовать»)

Одна вкладка на демона, дубли не открываются. Пассивный механизм — **именованный mutex**:

- **echotail** при старте создаёт mutex с именем от полного пути лога
  (`echotail-tab-<нормализованный путь>`; lowercase + не-[a-z0-9]→`-`) и держит хендл до
  выхода. Закрылась вкладка → ОС снимает mutex сама (kernel object). Несколько echotail на
  одном логе делят один mutex — «занят», пока жив хотя бы один.
- **echoctl `openLogTab`** перед открытием пробует `OpenMutex`: существует → вкладка уже есть
  → дубль не открывается. `openLogTab` становится функцией (Boolean «открыл») — `daemons tabs`
  честно печатает `tab: X` / `tab exists: X`.
- **launch_tab.ps1** — тот же чек через `[System.Threading.Mutex]::OpenExisting` (алгоритм
  имени идентичен); демон стартует windowless в любом случае, пропускается только вкладка.

Существующая вкладка сама показывает рестарт: ротация лога + маркеры `--watch-port`
(stopped → listening) — полная история в одной вкладке.

Худший случай рассинхрона имени (разное написание пути) = дубль вкладки, т.е. старое
поведение — деградация мягкая.

## Решения

- **TR-D1** переиспользование через именованный mutex от нормализованного пути лога; закрытие
  вкладки снимает mutex автоматически; алгоритм имени продублирован в echotail (standalone
  program) / echoctl / launch_tab.ps1 с пометкой «должны совпадать». (владелец: переиспользовать)
- **TR-D2** `openLogTab` → Boolean; `daemons tabs` печатает `tab: X` / `tab exists: X`;
  повторный `daemons tabs` идемпотентен.
- **TR-D3** старые echotail (без mutex, собранные до фичи) чек не видит → один одноразовый
  дубль до закрытия старых вкладок; допустимо.

## Фазы

- **P0** План + леджер.
- **P1** echotail публикует mutex — gate: у работающего echotail mutex открывается извне;
  после kill — не открывается; смоуки зелёные.
- **P2** Чек в echoctl + launch_tab — gate: повторный dev start / daemons tabs при живой
  вкладке НЕ открывает дубль (`tab exists`); после закрытия вкладки — открывает; dry-run
  launch_tab показывает чек.

## Конвенции

FPC по лекалу echotail/echoctl. Один шаг → один коммит → один гейт. Ветка `feature/tab-reuse`
от master (tail-stop-marker влит).
